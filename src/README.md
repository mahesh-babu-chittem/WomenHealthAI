# WomenHealthAI - Reproducibility and Reproduction Guide

## 1. Purpose

This document provides the complete reproduction information for the
**WomenHealthAI** project, including:

-   project-wide execution order;
-   working commands for Stages 1--9;
-   input and output dependencies between stages;
-   software and runtime requirements;
-   forecasting configuration;
-   explainability configuration;
-   LLM model, prompt, generation interface, and report storage;
-   evaluation procedures;
-   data-access and ethics requirements; and
-   a clear distinction between the implementation corresponding to the
    submitted results and subsequent repository corrections.

The repository is organized as a staged pipeline. Each stage consumes
outputs generated by preceding stages.

# 5. Data Access and Privacy

## 5.1 Study data

The WomenHealthAI pipeline operates on participant-level
reproductive-health data derived from the **mcPHASES** study/repository.

The original participant-level study data are **not redistributed in
this repository**.

The repository is intended to provide the computational implementation,
analysis procedures, result-processing scripts, and approved
non-identifying artifacts required to understand and reproduce the
analytical workflow.

Access to the underlying participant-level data must follow the original
study's:

-   data-access conditions;
-   ethical approvals;
-   institutional requirements;
-   participant-consent restrictions; and
-   applicable data-use agreements.

Researchers who do not have authorized access should not attempt to
reconstruct or redistribute participant-level records.

## 5.2 Public repository policy

Do not commit or redistribute:

-   participant names or direct identifiers;
-   participant-level reproductive-health measurements;
-   participant-specific dates where they could enable
    re-identification;
-   participant-specific predictions;
-   participant-specific explainability outputs;
-   participant-specific intervention records;
-   participant-specific LLM reports; or
-   other sensitive health information.

Aggregate statistics, model metrics, feature-importance summaries,
attention summaries, and other approved non-identifying outputs may be
retained where permitted.

## 5.3 Stage 8 reports

Stage 8 generates participant-specific health-guidance reports from
structured RHRS/risk/intervention information. These reports are
research artifacts containing sensitive participant-level information
and should remain inside the authorized research environment.

The LLM output is a research communication layer. It is **not a clinical
diagnosis and is not independently validated medical advice**.

-   Metabolic Resilience Score (MRS)
-   Behavioral Resilience Score (BRS)
-   Symptom Resilience Score (SRS)

and combines them into the overall Reproductive Health Resilience Score
(RHRS).

Run the five component calculations:

``` text
HORIZON = 7
```

``` text
HORIZON = 14
```


# 15. Exact Llama Model and Generation Interface

The Stage 8 implementation explicitly specifies:

``` text
Model: llama3:latest
Runtime/interface: Ollama
Python API: ollama.chat()
```

The generator calls:

``` python
ollama.chat(
    model="llama3:latest",
    messages=[
        {
            "role": "user",
            "content": prompt
        }
    ]
)
```

No explicit `temperature`, `top_p`, `seed`, or token-limit parameters
are passed to `ollama.chat()` in the submitted implementation.

Therefore:

> **No non-default generation parameters are claimed for the submitted
> results. The implementation relies on the defaults provided by the
> Ollama/model runtime available at execution time.**

The prompt's `Maximum 250 words` instruction is a **prompt-level
instruction** and should not be confused with an explicit model
`max_tokens`/token-limit parameter.

# 25. Data Access, Ethics, and Participant Privacy

WomenHealthAI uses the **mcPHASES dataset**, which contains
participant-level reproductive-health information.

The mcPHASES dataset is **not openly available for unrestricted public
download**. Researchers wishing to reproduce the participant-level
analyses must obtain access to the dataset through the appropriate
mcPHASES data-access process and comply with the conditions specified by
the dataset custodians.

The repository therefore does **not redistribute the original
participant-level mcPHASES data**. Instead, it provides the computational
code and approved non-identifying/aggregate artifacts required to
understand and reproduce the analytical workflow after authorized data
access has been obtained.

The reproduction process is therefore:

    Researcher
        |
        v
    Obtain authorized access to mcPHASES
        |
        v
    Place/access the authorized study data
        |
        v
    Run WomenHealthAI preprocessing and analysis pipeline
        |
        v
    Generate the corresponding research outputs

Researchers reproducing the study are responsible for complying with
the applicable:

- mcPHASES data-access requirements;
- ethical and institutional requirements;
- participant-consent restrictions;
- data-use conditions; and
- applicable privacy and data-protection requirements.

Participant-level data must not be uploaded to or redistributed through
the public repository.

Similarly, participant-specific outputs generated during reproduction,
including individual predictions, explainability outputs, intervention
recommendations, and LLM-generated reports, should remain within the
authorized research environment and must not be publicly redistributed
unless explicitly permitted by the applicable data-access and ethics
requirements.

The LLM component is a research communication layer. Its generated
health guidance should not be interpreted as a clinical diagnosis or as
independently validated medical advice.
